# 치팅 파인더 — 필기시험 부정행위 도감 + 감독관 게임 설계

서비스 이름: **치팅 파인더** (사용자 결정, 2026-11-17). 'XX냥이' 류 별명은 특정 개인을 떠올리게 해 쓰지 않는다.
상태: 승인됨(1차) → grill 반영 v2 (2026-11-17). 사용자 최종 확인 대기 항목은 §10.
선행 자료: [조사](../../research/cheating-methods.md) · [이미지 프롬프트](../../assets/image-prompts.md)

## 1. 의도와 이유

최근 필기시험 부정행위가 AI 안경·초소형 카메라·개조 계산기·위조 신분증 대리응시 등으로 기발해지고 있다 (세무사 시험 수석 사건, 정보처리기사·LEET·TOPIK 적발, 수능 직전 정부 대응).
이 사이트는 **누구나** 쓸 수 있고, 두 가지를 알게 한다.

1. **이런 수법도 있구나** — 국내·해외에서 실제로 보도된 수법을 한 곳에서 조회
2. **이렇게 알아챌 수 있구나** — 시험장 3×3 좌석에서 **반복되는 의심 행동**을 관찰해 수상한 응시자를 찾아 보며, 실제 감독이 쓰는 단서를 체험

도감과 게임이 **같은 사건 데이터**를 쓴다. 게임에서 잡으면 그 사건 카드가 열리고, 도감에서 읽으면 게임에서 알아볼 수 있다.

## 2. 목표 / 비목표 / 안티목표

**목표**
- 사건 도감(조회·필터·출처) + 3×3 감독관 미니게임 + 소맥식 결과 공유
- 한국뿐 아니라 해외 사례 포함
- 게임의 모든 의심 행동은 **실제 보도·감독 지침·커뮤니티 정리(구현 시 업계 설명 3종 추가, 독립 검증 아님 표시)에 존재하는 것만** 쓰고, 근거 종류를 화면에 표시

**비목표**
- 난이도 단계, 랭킹·서버 저장, 로그인, 멀티플레이, 사용자 제보·댓글
- 허브 지표(`/event`)·의견 위젯 연동 (필요해지면 별도)

**안티목표 (기술적으로 돌아가도 실패)**
- **따라 하기 안내서가 되는 것**: 장비 모델·설정·회피법·제작법을 싣지 않는다. 뉴스 수준 개요와 "알아챈 단서"만.
- **추정을 사실처럼 보이게 하는 것**: 사건에는 확인 라벨, 의심 행동에는 근거 라벨. 근거 없는 행동은 게임에 쓰지 않는다.
- **특정 개인을 부정행위자로 지목하는 것**: 실명·별명·계정명 금지. 온라인 의혹 단계 건(LEET 만점자 의혹 등)은 쓰지 않는다.
- **의심만으로 사람을 모는 게임이 되는 것**: 평범한 응시자를 반드시 넣고, 잘못 찍으면 "단일 행동만으로 단정할 수 없다"를 설명한다.
- **눈으로 못 잡는 수법을 눈으로 잡히는 것처럼 꾸미는 것**: 행동 단서가 없는 수법은 게임에서 빼고 도감에서 "알아채기 어렵다"고 설명한다.

## 3. 제약

- 한국어 UI. 모바일 우선 (카카오 인앱 브라우저, 세로 화면). 좌석 탭 영역 최소 44px.
- 서버 저장 없음. 도감 "발견" 표시는 localStorage (접근 실패 시 표시 없이 동작).
- 출처 URL 필수 (라벨이 `미검증`인 항목 제외). 면책 문구 상시: "뉴스 보도 기준 개요이며 따라 하기 안내가 아닙니다. 수사 중인 사건은 바뀔 수 있습니다."
- 에셋(도트 이미지)은 사용자가 생성한다 → 파일이 없어도 개발·테스트가 돌아가야 한다 (임시 그림). **공개 배포는 실제 에셋 교체 뒤에만 한다.**
- 외부 서비스에 사용자 정보를 보내지 않는다.

## 4. 접근 방식 (고려한 것과 선택)

**만드는 방식** — 선택: 바닐라 HTML/JS + 작은 Worker (사용자 선택). Vite+TS는 설정이 늘고 허브 코드 재사용이 줄며, Next.js는 서버 상태 없는 게임에 과함. 허브의 소맥·ASAP과 같은 구조(정적 페이지 + 순수 로직 JS + d.ts + vitest + 작은 Worker).

**화풍** — 선택: subwayrun 수준 도트 이미지 에셋 (사용자가 생성). 코드로 그린 도트(A, A′)는 품질이 낮고, 플랫(B)은 허브 게임들과 결이 맞지 않음.

**행동 표현** — 선택: **한 칸에 두 포즈(기본·행동)를 그려 교체** (사용자 선택 A). 한 장+코드 움직임은 시선·손 동작을 못 그린다.

**공유 이미지** — 선택: 칭호별 PNG를 미리 만들어 정적 제공, 숫자는 og:title 글줄. 런타임 SVG→PNG는 Worker 용량·폰트 부담, 소맥식 런타임 도트는 래스터 에셋과 안 맞음.

**행동 단서 근거 범위** — 선택: 근거 있는 12수법만 출전, 6수법은 도감 전용 (사용자 선택 B). "근거 없음 + 연출 라벨"은 기준에 어긋나 기각.

## 6. 설계 (내 판단 포함 — 고칠 수 있음)

### 6.1 데이터

`public/data/cases.json` — 사건/수법 한 건당:

```
id          예 "smart-glasses-frame"  (게임 출전 수법은 에셋 id와 동일)
name        "AI 스마트안경"
group       "device" | "collab" | "classic" | "proxy"
origins     [{ country: "KR", year: 2026, label: "정보처리기사 CBT" }, ...]   // 해외 포함
summary     뉴스 수준 한두 줄 (따라 하기 정보 금지)
cue         "알아챈 단서" 한 줄
detect      "감독이 확인하는 방법" 한 줄 (전파탐지·금속탐지·재검사·생체인식 등)
status      "confirmed" | "investigating" | "mentioned" | "unverified"
sources     [{ title, url }]            // unverified 외에는 1개 이상 필수
playable    boolean                     // true = 게임 출전 (tell 필수)
tell        { action, basisKind, basisSources[], intervalSec?, once? }   // playable일 때만
visibility  "low"                       // 행동으로 알아채기 어려운 수법(도감 전용 6종)이면 표시
```

`status` 라벨: `confirmed` 확인됨 / `investigating` 수사 중·일부 추정 / `mentioned` 거론됨 / `unverified` 미검증 소문(게임 제외, 도감 별도 코너).
`tell.basisKind`: `report`(보도) / `guideline`(감독 지침) / `community`(커뮤니티 정리) / `industry`(업계 설명, 독립 검증 아님). **`playable=true`이면 basisKind와 출처가 반드시 있다 (콘텐츠 테스트로 강제).** 근거가 수법에만 있고 행동 포즈는 연출인 경우(`phone-in-clothes`)는 `basisKind: "report"` + `basisNote: "수법은 보도, 행동 포즈는 연출"`로 화면에 그대로 표시한다.

`public/data/innocents.json` — 평범한 응시자 15명: `id`, `name`, `behavior`("oneoff" | "repeat"), `why`(의심스러워 보일 수 있는 이유와 왜 정상인지).

해외 사례는 기존 수법의 `origins`에 여러 나라로 붙인다 (예: AI 스마트안경 → 한국·일본·인도·대만). 새 수법이 나오면 에셋 시트를 추가 요청한다. "해외 포함" 판 구성 제약은 `origins`에 한국이 아닌 나라가 있는 수법을 뜻한다.

### 6.2 게임 규칙

**출전 수법 12종** (근거 있음): `smart-glasses-frame`, `glasses-lens-heat`, `earpiece-hidden`, `bone-conduction`, `smartwatch`, `phone-in-clothes`, `glasses-swap`, `earbud-swallow`, `ear-bandage`, `signal-fingers`, `peek`, `cheat-sheet-sleeve`. 행동은 [조사 G절](../../research/cheating-methods.md)·[이미지 프롬프트](../../assets/image-prompts.md)의 표를 따른다.
**도감 전용 6종**: 단추 카메라, 개조 계산기, 팔뚝 필기, 물병 라벨, 가방 속 폰, 위조 신분증.

**한 판**
- 60초, 기회 3. 3×3 좌석 9명 = 수법 응시자 3~4명(무작위, **해외 `origins` 수법 최소 1명**) + 평범한 응시자 5~6명
- 판 구성 시 일부 수법에는 **헷갈리는 평범한 응시자**를 같은 판에 넣는다 (스마트안경 ↔ 안경 올리기, 스마트워치 ↔ 아날로그 시계 확인, 귀 이어폰 ↔ 재채기·코 문지르기)
- 수법 응시자는 약 5초(±1.5초) 간격으로 행동 포즈를 0.8초 보임. 좌석별 시작 시점은 무작위 (동기화 금지)
- 평범한 응시자: `oneoff`는 행동 포즈를 판당 1~2회, `repeat`는 약 8초 간격으로 반복
- `glasses-swap`은 시작 약 20초에 포즈가 바뀌어 **이후 유지** (그 전에 탭하면 평범한 응시자로 취급되어 오해)
- 탭 판정: 수법 응시자 → 적발(그 좌석 "적발" 표시), 평범 → 기회 -1 + 그 좌석 "확인함" 표시. 이미 오해로 판정된 좌석은 다시 탭해도 무시한다. 게임 중에는 HUD 자리에 짧은 알림("적발! 이름 · 상태" / "정상 행동입니다 · 이름")만 2.5초 띄우고 좌석은 덮지 않는다. 사건 카드(상태·단서·근거·도감 링크)와 "단일 행동만으로는 부정행위라고 단정할 수 없습니다."(자체 안내 문구, 지침 인용 아님)는 결과 화면 목록에서 보여 준다 (아래 "구현 중 바뀐 결정")
- 종료: 수법 응시자 전원 적발 / 60초 종료 / 기회 0
- 화면에 항상 보이는 숫자: **남은 시간, 기회, "수상한 응시자 n명 중 k명 적발"**
- 기록: 잡은 수 `c`, 놓친 수 `m`, 오해 `f`, 전원 적발까지 걸린 시간 `t`(초, 전원 적발 못 하면 60). `c+m`은 3 또는 4

**칭호** (위에서부터 먼저 맞는 것):

| 칭호 | 조건 |
| --- | --- |
| 매의 눈 감독관 | `m=0`, `f=0`, `t<=30` |
| 베테랑 감독관 | `m<=1`, `f<=1` |
| 의심 많은 감독관 | `f>=3` |
| 신입 감독관 | `c>=2` |
| 졸고 있는 감독관 | 그 외 |

**최적 전략 점검** (grill에서 수행)
- 무작위 연타 (기회 소진): 수법 4+평범 5 → 3번째 오해 전 전원 적발 15/126 = 11.9%, 오해 0 완주 1/126 = 0.8%. 수법 3+평범 6 → 10/84 = 11.9%, 1/84 = 1.2%. 약 88%는 오해 3번으로 "의심 많은 감독관"
- "15초 관찰 후 반복 응시자만 탭": 15 ÷ 5 = 약 3회 관찰 → 20초 종료, `f=0` → "매의 눈". 시간 조건이 없으면 집중한 모두가 만점이라 `t<=30`을 둠. 30초는 초기값이며 플레이로 조정
- 아무것도 안 탭: 졸고 있는 감독관. 시간이 지나도 이득이 없음

### 6.3 도감

- 목록: 카드 격자. 필터 3축 — 국내/해외, 분류(전자기기·협력·고전·대리응시), 확인 수준. 도감 전용 6종은 "행동으로 알아채기 어려움" 표시
- 상세: 개요, 알아챈 단서, **의심 행동과 근거 라벨**(보도/지침/커뮤니티/업계), 감독 확인 방법, 출처, 연도·국가
- 게임에서 만난 수법에 "발견" 표시, 진행도 "n / 12"

### 6.4 페이지·라우팅

| 경로 | 내용 |
| --- | --- |
| `/` | 소개 + "도감 보기" + "게임 시작" |
| `/dex` (`/dex#id`) | 도감 |
| `/play` | 게임 |
| `/r?c=&m=&f=&t=` | 공유 랜딩: OG 태그 + 친구 결과 + "나도 해보기" |

### 6.5 공유 (소맥 방식)

- 결과 화면 "자랑하기": `navigator.share`, 안 되면 클립보드 복사, 클립보드도 안 되면 선택 가능한 링크 표시. 글에는 링크 하나만
- `/r` 핸들러: `c`·`m`·`f`·`t`를 정수로 검증 (`f` 0~3, `c+m` 3 또는 4, `t` 0~60, 아니면 `/`로 이동), 서버가 **칭호를 다시 계산**. og:title `잡은 c · 놓친 m · 오해 f`, og:description 칭호 문구, og:image `/og/<tier>.png?v=N`
- 링크 값은 누구나 조작할 수 있다. 랭킹이 없어 위조의 이득이 없으므로 서명은 하지 않는다 (제외)
- 칭호별 PNG 5장 (800×400). 에셋 도착 전에는 글자만 있는 임시 카드. 이미지 모양을 바꾸면 `v`를 올림

### 6.6 구조 (소맥·ASAP 규칙)

```
public/index.html, dex.html, play.html   각 페이지
public/game/logic.js (+ .d.ts)           판 구성(무작위·제약), 판정, 칭호, 공유 값 검증 — 브라우저·Worker 공용 순수 함수
public/game/scene.js                     좌석 그리기·포즈 교체·타이머·상단 짧은 알림
public/data/*.json                       사건·평범한 응시자
public/px/<id>-0.webp, <id>-1.webp       기본·행동 포즈 (에셋 전에는 임시 그림)
src/worker.ts                            /r 핸들러, 나머지는 정적 에셋
tests/                                   vitest
wrangler.jsonc                           workers_dev 사용은 에셋 교체 뒤
```

### 6.7 에셋 파이프라인

`images/` 시트 → 스크립트가 3×3 칸으로 자르고, 각 칸을 좌·우 포즈로 다시 나누고, 마젠타 배경을 투명 처리해 192×192 webp로 `public/px/<id>-0.webp`(기본)·`-1.webp`(행동) 저장 (표시 96px @2x). 소품 시트는 정사각 칸 그대로 `public/px/prop-*.webp`. 파일명은 프롬프트 문서의 id. 에셋 전에는 임시 그림을 같은 경로에 생성해 코드 변경 없이 교체한다.
총량: 응시자 27명 × 2포즈 = 54 + 소품 9 + 배경 1.

### 6.8 배포와 롤백

1. 로컬 개발·테스트 완료 (임시 그림으로 모든 기능 검증, **이 단계에서는 배포하지 않음**)
2. 사용자가 에셋 5장을 올림 → 제가 자르기·교체 → 점검 (프롬프트 문서 §8)
3. GitHub 저장소 생성·푸시 — **외부 공개 작업이라 그 시점에 한 번 더 확인**
4. `wrangler deploy` → workers.dev 주소 확인
5. 서브도메인 `cheatfinder.ktslab.xyz`는 대시보드 설정 가능 여부 확인 후. 허브 `games.json` 카드는 별도 PR (그 시점에 확인)
6. 배포 후 `/`, `/dex`, `/play`, `/r?c=3&m=1&f=0&t=40` 응답과 OG 태그 확인
- 롤백: 문제가 있으면 직전 버전으로 `wrangler rollback` 또는 직전 커밋 재배포. 데이터 마이그레이션 없음

## 7. 검증 방법

- vitest: 판 구성 제약(수법 3~4, 해외 ≥1, 중복 없음, 9칸, 헷갈리는 쌍 포함), 판정·칭호 경계값(`t=30` vs `31`, `f=2` vs `3`), 공유 값 검증(범위 밖·문자열·누락·`c+m` 위반), Worker `/r` 응답의 OG 태그
- 콘텐츠 검사 테스트: 모든 사건에 `status`, `unverified` 외 `sources`≥1, **`playable`이면 `tell.basisKind`·출처 필수**, 실명·별명 금지어 목록 미포함, 에셋 id 일치(기본·행동 파일 모두)
- 브라우저 확인: 375px·360px 폭 3×3 탭, 포즈 교체, 알림이 좌석을 가리지 않음, 결과 목록·공유 (e2e는 시스템 Chrome)

- ~~서울시교육청 지침 보도의 원문 URL 확인~~ → 원문을 찾지 못함. 지침 문구는 인용하지 않고, 귀 속 이어폰 근거는 업계 설명 + 2017 보도로 바꿈 (아래 "구현 중 바뀐 결정")
